# Настоящий OpenGL без видеокарты и без экрана

Этот документ описывает, как в окружении без root, без GPU, без дисплея и
с жёстким списком разрешённых хостов был получен работающий контекст
OpenGL 3.3 core — чтобы прогнать через него настоящий конвейер движка, а не
его эмуляцию.

## Почему это вообще проблема

Три причины складываются вместе:

1. **Нет прав суперпользователя.** `apt-get install` недоступен: пакетный
   менеджер не может взять блокировку `/var/lib/dpkg/lock-frontend`.
2. **Сеть ограничена списком хостов.** Доступны только `github.com`,
   `codeload.github.com`, `api.github.com`, `registry.npmjs.org`,
   `pypi.org`, `files.pythonhosted.org`. Зеркала дистрибутивов
   (`deb.debian.org`), GNU FTP, `gitlab.freedesktop.org` и даже
   **ассеты релизов GitHub** (`objects.githubusercontent.com`) закрыты.
   То есть все привычные каналы доставки бинарников отрезаны.
3. **Образ минимальный.** Есть `gcc`, `make`, `python3`, `node`, `git`.
   Нет `flex`, `bison`, `m4`, автотулзов, `cmake`, `meson`, `ninja`,
   `pkg-config`, нет заголовков `zlib`/`expat`, нет `libdrm`, нет `/dev/dri`,
   нет `DISPLAY`.

Остаются ровно два канала: **реестры пакетов языков** (npm и PyPI — там
бинарники попадаются, когда проект сам решил их вендорить) и **git clone
любого репозитория с GitHub** — в том числе такого, куда кто-то закоммитил
готовые бинарники или распакованный тарболл. На этих двух каналах всё и
построено.

## Цепочка

| Что | Откуда | Зачем |
|---|---|---|
| Free Pascal 3.3.1 | `git clone` репозитория `zeljkoc/pandroid`, в котором лежит вендоренная установка FPC (частичный клон с `--filter=blob:none` + sparse-checkout) | компилятор самого движка |
| `glslangValidator` | npm, `glslang-validator-prebuilt-predownloaded` | независимая проверка шейдеров |
| `flex` 2.6.4 | PyPI, `flex-bin` | нужен сборке Mesa |
| `bison` 3.8.2 | PyPI, `bison-bin` | нужен сборке Mesa |
| `m4` 1.4.18 | `git clone tar-mirror/gnu-m4` → сборка из исходников | bison запускает m4 как подпроцесс |
| `meson`, `ninja`, `Mako`, `PyYAML` | PyPI | система сборки Mesa |
| `pkgconf` | `git clone pkgconf/pkgconf` → сборка через meson | без него meson не находит зависимости |
| `zlib` 1.3.1 | `git clone madler/zlib` → `./configure && make` | обязательная зависимость Mesa |
| `libdrm` 2.4.134 | `git clone pronkproject/libdrm` → meson | Mesa требует её даже для программного рендера |
| **Mesa 26.3.0-devel** | `git clone intel-lgci-fdo-gitlab-mirror/mesa.mesa` (живое зеркало upstream на GitHub) → meson + ninja | `libEGL` и драйвер `softpipe` |
| `libglfw` 3.4 | PyPI, пакет `glfw` (в колесе лежит собранная библиотека) | нужна только для линковки, в безэкранном прогоне не вызывается |

Две ловушки по дороге, обе типовые:

* **Бутстрап m4.** `git` не хранит время изменения файлов, поэтому `make`
  решил, что `aclocal.m4` устарел, и полез за автотулзами, которых нет.
  Лечится расстановкой `touch` в порядке зависимостей. Дальше m4 1.4.18
  (2016 год) не собирается с современной glibc: макросы `_IO_*` убраны из
  `<stdio.h>`, а `SIGSTKSZ` перестал быть константой. Обе правки —
  по две строки, ровно те же, что накладывают Buildroot и Guix.
* **OSMesa больше нет.** Исторически безэкранный рендер в Mesa делался
  через OSMesa, и GLFW умеет её подхватывать (`GLFW_PLATFORM_NULL`).
  Но из современной Mesa фронтенд OSMesa удалён — в дереве его просто нет.
  Поэтому контекст создаётся напрямую через **EGL на платформе
  surfaceless**: контекст без окна и без поверхности, рисование в
  framebuffer-объект, чтение через `glReadPixels`.

## Как воспроизвести прогон

```sh
export MESA=/путь/к/prefix
LD_LIBRARY_PATH=$MESA/lib/x86_64-linux-gnu \
EGL_PLATFORM=surfaceless \
  ./build/render_gl
```

Вывод:


## Что этот прогон проверяет

Всё то, чего не мог проверить программный растеризатор:

* создание контекста и загрузку указателей на функции GL;
* **компиляцию и линковку шейдеров настоящим компилятором GLSL драйвера**;
* поиск и установку uniform-переменных;
* VAO, VBO, индексные буферы, буфер экземпляров и — главное — совпадение
  раскладки записи `TInstance` (80 байт, матрица по смещению 0, цвет по 64)
  с тем, что передаётся в `glVertexAttribPointer`;
* `glDrawElementsInstanced`, отсечение задних граней, тест глубины;
* отсутствие ошибок GL на всём пути (`gl_check` после каждого этапа).

Найденная этим прогоном настоящая ошибка: Free Pascal **не маскирует
исключения сопроцессора**, а драйвер GL внутри себя спокойно делит на ноль
и ждёт тихих `inf`/`nan`. Без `SetExceptionMask` приложение падает с
`EZeroDivide` в недрах драйвера — на любой машине, не только здесь.
Строчка добавлена в `main.pas`.

## Сверка с программным растеризатором

Один и тот же кадр, нарисованный настоящей Mesa и модулем `tests/usoftgl.pas`:

```
кадр 1280x720, каналов 2764800
средняя разница: 0.02 из 255 (0.01%)
  отличие     <=2:  99.95%
  отличие    3..8:   0.01%
  отличие   9..24:   0.04%
  отличие  25..64:   0.00%
  отличие     >64:   0.00%
```

Расхождения — тонкие контуры на силуэтах сфер: у растеризатора превью нет
мультисэмплинга и правила «верх-лево» при заполнении. Внутри полигонов
освещение, туман, гамма и глубина совпадают с точностью до округления.
